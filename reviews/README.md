# `reviews/`

Review passes that are deliverables in their own right, with the instruments
that produced them checked in beside the findings.

| | |
|---|---|
| `2026-09-01-fd-8-anti-pattern-review.md` | doc 06 §8's ten anti-patterns, checked one by one. The Phase 4 sign-off deliverable of doc 06 §9 (RM-050, #58). |
| `probes/` | The measurements. One file per anti-pattern, plus probe 0, which measures the instrument. |
| `harness/` | What the probes measure with: a render gallery, a CSS resolver, a perception model, and a way to attempt a violation. |
| `evidence/` | What the probes recorded, verbatim. Regenerated by re-running them; committed so the review can be read without running anything. |

## Running the probes

```bash
cd web
npm run build                                        # the probes read dist/assets/*.css
npx vitest run --config ../reviews/harness/vitest.config.ts
```

The probes are a **separate vitest project** from the dashboard's own suite.
They are not in `web`'s default include glob, they do not change its test count,
and `web/vite.config.ts` is not this issue's file to edit. They read
`web/src/**` and write only `reviews/evidence/`.

`npm run build` first, always: the colour half of this review is a join between
the DOM a component rendered and the stylesheet the build compiled. A stale
`dist/` measures a stylesheet nobody ships.
