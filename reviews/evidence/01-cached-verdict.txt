── FINDING: the required prop has no required field ──────────────────────────

    VerificationPanel.tsx states the guarantee in these words:

        "Required, a view that caches and stays quiet does not compile.
         Same move as ADR-0038 decision 3 — remove the step that can be
         wrong rather than check it afterwards."

    Measured, that holds for an OMITTED prop and not for an EMPTY one.
    `Liveness` declares `source?: "live" | "cache"` — optional — so:

    import { VerificationPanel } from "../../src/components/verification/VerificationPanel";
    import { verifiedProof } from "../../src/components/verification/fixtures";
    
    export const attempt = <VerificationPanel proof={verifiedProof()} liveness={{}} />;

    RESULT: the compiler ACCEPTED it.

    And this is what that empty object paints, measured the same way as
    every other scene above:

        badge reads   "Verified"
        painted       color=#116039/#6ccf95 (green/green)
        painted       background-color=#e6f4ec/#062e1c (green/green)
        painted       border-color=#167a49/#3cb573 (green/green)

    So a caching view that writes `liveness={{}}` gets the green, and the
    type system does not object. Two facts bound how much this matters:
    nothing in web/src passes an empty object (grep recorded below), and
    the two callers that DO hold retained answers narrow the type so that
    `source` is required — views/runs/proofs.ts's StatedLiveness and
    views/overview/types.ts's MeasuredLiveness. The hole is in the panel's
    own contract, not in any shipped call site.
